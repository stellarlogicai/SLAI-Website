# ServicesOS Internal Beta Scope

This document defines what is in scope and out of scope for wife beta and early internal ServicesOS testing.

ServicesOS is priority one. This beta is focused on the cleaning and service business workflow.

## In Scope

- Login.
- Customer/lead workflow.
- Estimate workflow.
- Contract or booking workflow if available.
- Scheduling.
- Employee assignment.
- Employee checklist/job completion.
- Admin status visibility.
- Basic payment status tracking if available.
- Dashboard loading and basic counts.
- Bugs and confusion.
- Mobile usability for the tested workflow.
- Data persistence after refresh.
- Owner and employee view agreement.

## Out of Scope

- Tap to Pay.
- Food truck module.
- GrowthAI.
- EducationOS.
- ComplianceAI.
- FutureAI.
- Advanced automations.
- Perfect UI polish.
- Full public launch.
- Exact final pricing.
- Subscription purchase flow.
- Automated onboarding.
- Advanced analytics.
- Future vertical/module ideas.

## Scope Rules

- Do not turn future ideas into beta-critical bugs.
- Do not judge the beta based on Tap to Pay.
- Do not judge the beta based on future products.
- Do not block wife beta because of a nice-to-have feature.
- Do block wife beta if the core ServicesOS workflow cannot continue.

## Priority Reminder

Fix order should stay focused:

1. Data loss or incorrect saves.
2. Login and tenant/account loading.
3. Core workflow blockers.
4. Employee workflow blockers.
5. Payment status issues.
6. Wife beta confusion points.
7. UI polish.
8. Later features.
