# First ServicesOS Fix Sprint Plan

## Goal

Fix the highest-priority ServicesOS beta issues found during manual testing so wife beta can continue and the core cleaning/service business workflow becomes stable enough for trusted feedback.

## What Qualifies for the First Fix Sprint

- Data loss or incorrect saves.
- Login failures.
- Tenant/account loading failures.
- Customer/lead creation blockers.
- Estimate, booking, scheduling, assignment, job completion, or dashboard blockers.
- Employee workflow blockers.
- Misleading payment status or job status.
- Wife beta confusion points that stop a basic job from being completed.

## What Does Not Qualify

- Tap to Pay.
- Advanced analytics.
- Future automations.
- Future vertical/module ideas.
- Cosmetic polish that does not affect use.
- Non-ServicesOS product ideas.
- Pricing or checkout scope.

## Fix Order

1. Data loss / save bugs
2. Login / tenant loading bugs
3. Core workflow blockers
4. Employee workflow blockers
5. Payment status issues
6. Wife beta confusion points
7. UI polish
8. Later features

## Retest Process

- Re-run the failed scenario.
- Confirm the original bug is fixed.
- Confirm the fix did not create a new core workflow bug.
- Test desktop.
- Test mobile/tablet if the issue affects smaller screens.
- Verify saved data persists after refresh.
- Verify admin and employee views agree when both are involved.
- Update the bug fix queue with retest results.

## Exit Criteria

- No open blocker bugs in the tested core workflow.
- No open beta-critical bugs blocking wife beta.
- Payment status limitations are documented.
- Tap to Pay remains out of the beta-critical list.
- Confusing UI items are recorded with severity.
- Retest checklist is complete for fixed issues.
- Next wife beta run has a clear scenario and known limitations.
